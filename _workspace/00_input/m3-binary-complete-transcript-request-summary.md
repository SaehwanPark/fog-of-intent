Prove that a clean checkout can complete the bounded two-window fixture through
the real executable stdin/stdout loop using documented public commands.

- Add one binary integration transcript using the supported versioned fixture
  ID and the line-oriented command loop.
- Exercise observation, message/contingency staging, two commits, both window
  advances, current replay verification, debrief, and quit.
- Assert success status, labeled actor-safe output, and the expected first/
  second-window, replay, debrief, and quit markers.
- Synchronize the M3 exit-evidence docs and retain the existing library/store
  and process-argument tests.

## Out of scope

- New host or lane behavior, scenario mechanics, persistence semantics, branch
  graphs, terminal-specific prompts, or human accessibility evaluation.
- Treating one fixture transcript as a complete playable scenario, balance,
  enjoyment, or behavioral-validity result.

## Success evidence

- The executable completes the documented transcript from a clean process with
  no stderr and a successful status.
- The binary evidence is distinct from library-only host and two-process store
  evidence, and docs state the bounded transcript and its limits precisely.
